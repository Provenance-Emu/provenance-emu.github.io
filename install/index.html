Install Provenance

Free iOS game emulator for iPhone, iPad, and Apple TV. Choose your install method below.

App Store Recommended

The easiest way. Automatic updates, no computer needed. Provenance is 100% free on the App Store.

  • Works on iPhone, iPad, and Apple TV
  • Automatic updates via the App Store
  • Optional Provenance Plus for iCloud sync & beta access

AltStore

Sideload directly via AltStore. Tap "Add Source" to add the Provenance source, then install from the Browse tab.

  • Requires AltStore on your iPhone/iPad and AltServer on your Mac or PC
  • Refresh every 7 days (or use AltStore PAL on EU devices — no refresh needed)
  • Source URL: https://provenance-emu.com/apps.json

SideStore

Sideload wirelessly without a computer using SideStore. Tap "Add Source" to add Provenance.

  • Fully on-device — no Mac or PC required after initial setup
  • Refresh every 7 days using SideStore's built-in VPN trick
  • Source URL: https://provenance-emu.com/apps.json

IPA / Build from Source

Download the latest IPA and sideload manually, or build Provenance yourself from the open-source code.

  • Requires Xcode 16+ and an Apple Developer account (free or paid)
  • Full source available on GitHub under the Provenance License
  • See the build guide for step-by-step instructions

Which iOS IPA?

FileApp IDs usedTrade-off
Provenance-iOS-NoExtensions.ipa1No widgets, Spotlight, QuickLook, stickers, or Files.app ROM provider. Import ROMs via the built-in web server.
Provenance-iOS.ipa~9Everything included.

A free Apple ID can register only 10 App IDs per 7 days, and every
embedded extension consumes one — so the full build can use up almost
your entire weekly quota in a single install. The sideload feed serves
the NoExtensions build for that reason; grab the full IPA above if you
have a paid developer account or want the extensions.

This release is automatically updated on every successful develop push.

What's New in 3.3.0

This is a big one. Four months of work since 3.2.1 covering iCloud sync, a completely revamped tvOS interface, video filters, and a ton of core and stability fixes.

☁️ iCloud / CloudKit Sync

  • ROMs, save states, BIOS files, and artwork now sync across devices via iCloud
  • Real-time download progress indicators when loading cloud save states
  • Auto BIOS sync on game load when available in iCloud
  • ROM metadata syncs alongside files
  • Artwork syncs after library updates
  • CloudKit records management tab in Settings
  • iCloud upsell UI for new users with empty libraries
  • Sync queue pauses during emulation and resumes after

📺 New tvOS UI (Default)

  • Completely redesigned tvOS interface now enabled by default
  • RetroWave-themed side menu with smooth animations
  • Save states browser accessible from the main UI with artwork and core name
  • "View All" saves section with per-system filtering
  • TopShelf v2: recent games and save states with artwork and timestamps
  • Cheats UI in the pause menu
  • Game "More Info" panel
  • Log viewer tab
  • Import status view in side menu
  • Search with persistent history
  • Dozens of focus, navigation, and theming fixes throughout

🎨 Video Filters & Shaders

  • Unified filter pipeline works across native and RetroArch cores
  • GB and VHS filters improved
  • Filters accessible from the pause menu
  • RetroArch GLES 3D cores now supported (Vecx/GLiden, etc.)
  • Dolphin shader/filter support
  • PPSSPP filter support

🎮 Core & Controller Fixes

  • RetroArch: Fixed player index mapping for MFi, PS4, and Xbox controllers; PS4 start/select fixed; 32x controls added; GameCube controller responder added
  • Mupen64Plus: Fixed PS4 start button; fixed tvOS scaling and placement; better save error messages
  • Dolphin: Fixed Vulkan landscape rendering
  • GenPluGX: Added CHD support; added wide-screen GameGear core
  • PicoDrive: Fixed crash on unload; fixed 32x controller mapping
  • FCEUmm: Fixed start/select button mapping
  • Mednafen: Fixed DualShock/DualSense pause/play button mapping
  • GameBatte / TGDB Dual: Fixed PSX/Xbox pause/select button mapping

🐛 Bug Fixes & Stability

  • Fixed multiple app hangs from main-thread Realm access (moved to background)
  • Fixed crash in pause menu when closing core
  • Fixed potential crash if audio ring buffer init fails
  • Fixed crash in share/import extension
  • Fixed aspect ratio issues in Stella and some other cores
  • Fixed FPS label appearing in screenshots
  • Fixed artwork not refreshing in game library after sync
  • Fixed game importer re-queuing already-imported items
  • Fixed Realm contentless core crash
  • Fixed "Continue" carousel metadata mismatch
  • Skin selector refreshes orientation previews on rotation change
  • ManicSkin/DeltaSkin files can now be opened directly from Safari
  • iPad import status modal clipped layout fixed
  • DSP audio engine fixes

⚡ Performance

  • Artwork loading significantly faster
  • Game library UI rendering optimizations (removed unnecessary Observable wrappers)
  • Async tab bar icon loading
  • CloudKit sync deduplication and repeat-lookup fixes
  • Game importer skips MD5 hashing for large non-BIOS files

Touch controls that feel right

  • Optional high-contrast touchpad overlay with proper multi-touch
  • Motion sensitivity (gain), deadzone, smoothing: dial it in your way
  • Better visual feedback and cleaner UI while playing

  • Complete DSU implementation - Turn your iOS device into a wireless controller for tvOS/PC
  • Multiple controller layouts - Apple Virtual, GameCube, Wii Remote, Classic, and Sideways
  • Smart motion controls - Choose between Gyro, Follow, or Drag for IR pointer

  • Real-time status HUD - See connection status, TX/RX counters, and client info
  • Targeted sending - Choose specific receivers or broadcast to all
  • Touch area overlay - Visual touchpad for precise cursor control
  • Tooltip system - Learn what each button does with helpful hints
  • Apple Virtual Controller - Native iOS touch controls with D-Pad/Stick toggle

🖥️ tvOS Love

  • Full-screen pause menu - Auto-shows when app backgrounds, respects your flow
  • No keyboard nonsense - Mapping and settings built for the remote/controller
  • Clean visuals - Less clutter, more play
  • Enhanced focus effects - Beautiful cyan/purple glow animations

🎨 Visual Polish

  • Enhanced fonts - Rounded system fonts with iOS 16+ compatibility
  • Smooth animations - EaseInOut transitions and haptic feedback
  • Better contrast - High-contrast touchpad overlay option
  • Premium feel - Inner highlights, shadows, and depth effects

⚙️ Quality-of-life upgrades

  • Shader list search - Find what you need without scrolling
  • Quick graphics controls - Right from in-game overlays
  • Smarter defaults - iOS as controller, tvOS as console
  • Better discovery - Devices show up where you expect them
  • Motion customization - Fine-tune sticks with soft snap-to-center

�� Known issues (beta)

  • DSU IR cursor - Still inconsistent in some setups (especially with mixed gyro/touch inputs). If your cursor drifts or "fights" you:
  • Try turning off "Send Gyro/Accel" and "Map IR to Touch" for pure touch cursor
  • Switch Touch IR Mode between Gyro / Follow / Drag to see what your game prefers
  • Re-enter the controller view to reset motion and cursor state

🚀 Stability & performance

  • Fewer random crashes (threading and discovery hardened)
  • Snappier input round-trip and more reliable reconnects
  • Touch and motion won't step on each other anymore

�� Pro tips

  • Want pure touch cursor? Turn off "Send Gyro/Accel" and "Map IR to Touch"
  • Motion too twitchy? Lower Gyro Gain in Motion Settings
  • Swapping layouts a lot? Use the toolbar Layout button in-game
  • Love the GameCube vibe? Try "GameCube Gradient" in library background settings

What’s new

Virtual Jaguar libretro v3.8.0

Correct by default. Flip Out runs, Fight For Your Life boots on the real BIOS, Club Drive
has sound under HLE, White Men Can't Jump stops tearing, and Doom netplay holds 60 fps.

v3.8.0 is the "Correct by default" release (milestone "v3.8.0 — Correct by default", epic
#746). It fixes titles that needed a non-default setting or misbehaved in one boot mode,
makes the per-title database explain itself in the frontend, and adds a release gate that
blocks a tag when any corpus row moves backward. There is one new core option (the
GameDrive SD card) and one new value for an existing option. The savestate format moves
from v16 to v17; v3.7.1 and older states still load (see Savestates).

Several fixes here are verified headlessly only, not yet in RetroArch. Each one says so
below, and they are collected under Known issues.

Highlights

  • Flip Out runs in both boot modes. 1, 2 and 4 MB cartridge images now repeat across
    the cartridge window as on hardware (#855, #851).
  • Fight For Your Life (1996) boots on the real BIOS. Power-on RAM is now zero-filled in
    BIOS mode, as it already was in HLE (#868, #856).
  • Club Drive has audio under the default HLE boot. DSP interrupts are taken at the
    DSP's next instruction instead of inside an event callback (#849, #744).
  • White Men Can't Jump gameplay stops tearing at default settings, through a new
    "68000 only" value for Blitter Bus Timing (#870, #736).
  • Music Demo, Ruiner Pinball and Native Demo (bin) no longer run their DSP or GPU into
    garbage     (#862, #869, #872, #873).
  • Doom 2-player netplay holds 60 fps instead of dropping to 30 Hz. Play over Wi-Fi is
    still slower than single player (#861, #871, #860).
  • The GameDrive SD card works, backed by a folder on your device (#844, #783).
  • The frontend explains per-title presets, and options that apply only at load say so
    (#847, #859, #863).

Game fixes

Cartridge titles

  • Flip Out (#851, #855). The game checks the long at $A02000 and executes ILLEGAL
    if it does not match. A 2 MB cartridge drives only the address lines it has, so on
    hardware its image repeats at $A00000; the core returned 0 there. HLE looped
    ILLEGAL/RTE from about frame 320 and BIOS trapped into the boot ROM at about frame
    810. Images of exactly 1, 2 or 4 MiB are now mirrored (1 MB every MB, 2 MB at $A00000
    and $C00000, 4 MB once at $C00000), matching the MiSTer core's cart_mask; the JTRM is
    silent on this. In a headless run HLE reaches the high-score screen by frame 1000 and BIOS
    the title screen by frame 1200. A 160-cart A/B changed only Flip Out, plus one pixel in
    Fight For Your Life, where a blit reads past the end of the 4 MB image. The cart window
    past an image is also cleared on load, so a previous title's bytes no longer survive a
    reload in the same session. Headless-verified only.
  • Fight For Your Life (1996), real BIOS (#856, #868). The game sizes a fill from a RAM
    word nothing ever writes. BIOS mode filled power-on RAM with a per-word random pattern,
    so the fill overran into the GPU's parameter block, the GPU wrote a bad pointer, and the
    68K took an address error into the boot ROM at frame 1032. HLE zero-fills and never hit
    it. BIOS mode now zero-fills too. Power-on DRAM contents are undefined on hardware, but
    real parts come up in near-uniform runs, not independent random words. RAM-loaded images
    and the first 8 bytes are still preserved. One known cost: the JaGol intro seeds its Game
    of Life from power-on RAM and now shows an almost empty field (see Known issues). test_ffyl_856 now runs 1400 frames to game
    code. The good dump is CRC B14C4753; the [a1] dump is an authentic BIOS reject.
    Headless-verified only.
  • Club Drive audio under HLE (#744, #849). Club Drive was silent under the default HLE
    boot (in a sweep of 97 start-up I2S phases, 5 were silent on develop and 0 with the fix). The core vectored the DSP inside the I2S event
    callback; the 68K then rewrote D_PC while the DSP was running (JTRM v8 p.110 allows that
    only while it is idle), so the interrupt service routine never ran and the game never
    re-armed it. The interrupt is now latched and taken at the DSP's next instruction.
    Club Drive HLE went from RMS 0.0 to 2948.6. A 160-cart A/B was framebuffer-identical in
    both modes, and the audio pair is unchanged on Wolfenstein 3D, Doom, White Men Can't Jump,
    Iron Soldier 1 and 2, Skyhammer, Atari Karts, Raiden, Tempest 2000 and Zoop. Confirmed by
    ear in RetroArch on iOS (Doom, Wolfenstein 3D, Club Drive, Music Demo).
  • White Men Can't Jump gameplay tearing (#736, #870). v3.7.1 turned Blitter Bus Timing
    on for this title to fix its intro logo. That also made the GPU wait out each of its own
    blits at worst-case cost, so the GPU's draw started late and in 86 of 125 fields was
    still running when the 68000 swapped buffers: horizontal tears and sprites missing for a
    field. Blitter Bus Timing gains a "68000 only" value that stalls just the 68000, and
    the title's preset now uses it. The intro logo fix still holds (boot frames 0-300 hash
    identically; the logo is 43.8% lit). Over two 600-frame stretches of the attract match,
    reverted frames / spliced frames went from 68/12 and 95/15 to 21/2 and 23/4. Some
    flicker remains. Headless-verified only (fb_flicker_probe).
  • Music Demo DSP runaway (#853, #862). The DSP code stores D_FLAGS to change register
    bank and then sets r31 in the next instruction. On hardware that instruction still sees
    the old bank (JTRM v8 p.109); the core switched immediately, so the stack pointer landed in
    the wrong bank and the first interrupt returned into garbage. The bank switch now waits
    out the two-instruction retire window, and jump/jr commit it before their delay slot
    so the Doom and Wolfenstein 3D epilogues behave as before. A 160-cart A/B (HLE and BIOS,
    1200 frames, framebuffer and audio) was byte-identical except Music Demo. The crash
    watchdog now also sees DSP runaways in HLE. Confirmed in RetroArch on iOS: Music Demo
    runs in both modes with no watchdog lines.
  • GPU G_FLAGS retire window (#865, #869). The GPU gets the same two-instruction window
    as the DSP. No title is known to change. Unit-tested (test_gpu_ops 66/66). A partial
    corpus A/B (98 carts, 1200 frames) was 98/98 identical in HLE and 96/98 in BIOS, the two
    differences being harness artifacts, and the release cart matrix (which includes this
    change) has no backward row. A per-frame A/B of the whole corpus and a visual check are
    still owed.
  • Ruiner Pinball GPU escape (#866, #873). store Rn,(r15+Rm) was the one GPU long-store
    form that did not drop the low address bits, so a word-aligned store split across two
    longs, a jump table went wrong and the GPU ran off into DSP RAM at frame 56. Every form
    now aligns, as the MiSTer RTL addresses GPU local RAM by bits 11:2 only. Ruiner Pinball
    loses its gpu_pc_escape and video_stall in both modes. The core does not yet claim the
    game is playable. Headless-verified only.
  • Native Demo (bin) boots (#866, #872). This headerless binary is linked at $5000,
    but every address it uses also fits $4000, so the loader picked $4000 and the GPU ran
    away at frame 1. On a tie the loader now prefers the base under which LEA targets point
    at Jaguar I/O descriptor tables. Across 141 resolvable carts only this title changes base.
    It now reaches game code with video in both modes, like the .jag version.
    Headless-verified only.

What’s new

Virtual Jaguar libretro v3.7.0

Broken-games release. Most of the fixes are for Jaguar CD titles that froze, showed a
black screen or would not boot, plus two cartridge fixes, three blitter fixes and an
OP fix. HLE-mode CD titles now behave under run-ahead and rollback.

v3.7.0 is the first of the two trains that follow the 2026-09 re-plan (epic #745,
milestone "v3.7.0 — Broken games"). It is about titles that did not boot, froze, or
showed a black screen. There is no performance work in this release and no new core
option. The savestate format moves from v14 to v15; new builds still load v14 states
(see Savestates).

Fourteen of the commits since v3.6.1 are by Adrien Beudin (@beudbeud), who found and
fixed most of the Jaguar CD problems below. GitHub only lets the author mark a fork's
draft PR ready, so most of those arrived through carrier PRs that merged the original
commits unchanged. Authorship is preserved on the commits.

Highlights

  • Baldies no longer freezes ~600 frames into its intro in the default HLE boot
    mode, and no longer wedges under cd_boot_mode=bios either (#738, #750, #752).
  • Myst boots from CHD images, and gets past the Cyan logo in both boot modes
    (#754, #755, #756, #757).
  • World Tour Racing gets past its title screen (#589, #759).
  • PolyEngine (42Bastian's demo) boots and draws polygons (#785, #790, #791).
  • PlaySFX and other headerless raw-binary homebrew load in HLE (#739, #805).
  • Vid Grid, Ocean Depths, Simone, Fast Food 64, Frogz 64 and
    Saucer Wars each have a fix (#760 through #765, with #762 for Vid Grid's video).
  • HLE CD titles are deterministic under run-ahead and rollback, and a state saved
    in the middle of a CD load resumes the load (#787, #803).
