App Store

Recommended

The easiest way. Automatic updates, no computer needed. Provenance is 100% free on the App Store.

  • Works on iPhone, iPad, and Apple TV
  • Automatic updates via the App Store
  • Optional Provenance Plus for iCloud sync & priority support

AltStore

Sideload directly via AltStore. Tap "Add Source" to add the Provenance source, then install from the Browse tab.

  • Requires AltStore on your iPhone/iPad and AltServer on your Mac or PC
  • Refresh every 7 days (or use AltStore PAL on EU devices — no refresh needed)
  • Source URL: https://provenance-emu.com/apps.json

SideStore

Sideload wirelessly without a computer using SideStore. Tap "Add Source" to add Provenance.

  • Fully on-device — no Mac or PC required after initial setup
  • Refresh every 7 days using SideStore's built-in VPN trick
  • Source URL: https://provenance-emu.com/apps.json

IPA / Build from Source

Download the latest IPA and sideload manually, or build Provenance yourself from the open-source code.

  • Requires Xcode 16+ and an Apple Developer account (free or paid)
  • Full source available on GitHub under the Provenance License

  • Fixed crash in share/import extension
  • Fixed aspect ratio issues in Stella and some other cores
  • Fixed FPS label appearing in screenshots
  • Fixed artwork not refreshing in game library after sync
  • Fixed game importer re-queuing already-imported items
  • Fixed Realm contentless core crash
  • Fixed "Continue" carousel metadata mismatch
  • Skin selector refreshes orientation previews on rotation change
  • ManicSkin/DeltaSkin files can now be opened directly from Safari
  • iPad import status modal clipped layout fixed

The emulation thread is on by default, with "Match display" pacing, community cheats in the app, a finished TV mode, faster GPU and DSP emulation, and AvP's marines fight back.

This is a feature release for the standalone app on macOS, Windows and Linux. The libretro core gains the AvP and GPU/DSP changes below. Core options and v17 savestates carry over.

The emulation thread is on by default

The app now runs the emulation on its own thread in every build, so the UI, menus and tool windows no longer slow the game down. (#1134)

  • Tools and the debugger work with the thread on. This covers the Tools windows, debugger halts, single-stepping and the GDB stub. Detach, Reset, Open and Close release a halt that GDB holds. (#1061, #1068, #1090)
  • Neuro AI players run on the emulation thread too. (#1066)
  • Settings > Video > Frame pacing offers two modes:
    • Jaguar rate, the default, runs the game at the console's own rate.
    • Match display starts every frame on a display refresh, and the audio follows the display. The game runs at the display's rate (on a 60 Hz screen, 0.1% slower than a Jaguar) with no repeated or skipped images. Where the display can't be locked, the status line says why and Jaguar rate is used. (#1125, #1128)
  • The emulation thread asks for real-time scheduling, so frames start on time on a busy machine. macOS uses a time-constraint thread, Windows a time-critical thread in the MMCSS "Games" task, and Linux SCHED_RR where the system allows it. (#1135)
  • Rolling back: set Settings > Interface > Emulation thread to Off, or start the app with --emu-thread off. Without the thread, the app no longer repeats and drops frames in bursts as the display's refresh drifts against the console's. (#1145)
  • To report a threading problem, follow the app README. (#1131)

Community cheats

  • Cheats > Community cheats installs, updates or removes the pack the project site publishes for the loaded cartridge.

    • Packs are matched to the cartridge's CRC32.
    • Every cheat starts off.
    • Hardcore achievement mode is respected.

    Library > Download art and cheat packs fetches packs for the whole library. (#1073, #1076)

Desktop app

Controller-friendly TV mode, a more responsive desktop app, multi-disc playlists, and optional AI players.

This is a feature release for the standalone app on macOS, Windows and Linux. It also includes MMULT and TOM register-readback corrections from AtariAge reports. Core options and v17 savestates carry over. Experimental emulation threading remains off by default.

Play from the couch

  • TV mode adds Home, Library and Game details screens and a paused in-game menu designed for a controller. Hold the configured TV-menu button to open it, or use Ctrl/Cmd+Shift+T to toggle TV mode. Initial setup still uses desktop mode. (#995, #999, #1024)
  • Desktop library controller navigation, with per-family and custom button profiles. (#1030)
  • Jaguar Pro Controller support exposes X, Y, Z, L and R as separate controls. (#1019)
  • Fullscreen menu auto-hide is optional. Detached tool windows use the native operating-system title bar, without duplicate in-app window controls. (#1034)

Desktop responsiveness

An optional emulation thread lets the UI keep responding while the core runs. RetroAchievements evaluation and link play run on the core owner thread; long operations show a busy indicator. Command ordering, achievements UI access and shutdown races are covered by regression tests, including ThreadSanitizer tests in CI. (#1000, #1031, #1033)

Presentation pacing and late input latching have more precise wake-ups, more deadline headroom and slower safety-pad decay. (#1018, #1023, #1035)

The setting is under Settings > Interface > Performance > Emulation thread and takes effect after restarting. Keep it off to use the Tools/debugger windows or GDB: those features still need to move across the thread boundary. Rare host scheduling stalls and display-rate pacing remain follow-up work; this release does not claim to eliminate every repeated frame.

Community cheat conversion

An optional offline source converter turns supported community-authored C memory freezes into .cht files, including grouped writes and bounded loops. Unsupported operations are reported for a manual port. Generated sets start disabled and the app checks the cartridge CRC32 before applying them. Pinned community sources are tested in CI; no community cheat pack, emulator binary, or SDK is bundled. (#1052, conversion guide)

Emulation corrections

  • GPU and DSP MMULT preserve the advanced matrix-address counter and wrap coefficient reads within local RAM. Consecutive multiplies now render the supplied polygon demo as a filled solid instead of a line. Row/column stepping, address wrap and matrix-address savestate round trips have regression coverage. (#1043)
  • TOM PIT reads expose live timer counters. Unreadable TOM I/O registers fall back to MEMCON1, following the original Atari netlists. Timer reads use the existing scheduler and have scheduler-slice resolution; independent prescaler phase during partial reprogramming remains future work. (#1044, #1045)
  • The fast blitter uses the A2 destination lanes for computed Z and Gouraud gradients when DSTA2 is selected. A bootable greater-than Z test reproduces the incorrect writes before the fix and passes afterward. Regression cases cover both engines, mixed pixel/phrase modes, signed increments and phrase boundaries. (#1046, #1051)

Jaguar CD and achievements

  • Open .m3u multi-disc playlists; every disc appears under File > Disc. (#1012)
  • Invalid playlists no longer hide otherwise playable discs. States from every playlist disc remain available in the library and TV mode, including identical slot numbers on different discs. Resuming mounts the state-owning disc while retaining the playlist's full disc list and save-RAM ownership. (#1042)
  • The disc menu works after loading a CD and while booted into the CD BIOS without a disc. Swaps update the running content identity while keeping save ownership on the disc that opened the session. (#1006, #1009, #1011)
  • The achievements browser omits games with no achievement set. (#1015)
  • Missing CD mirror artwork is remembered only for the current session, so later launches can retry. The website also offers the CD artwork collection as one ZIP. (#998, #1016)

AI players

Settings > Neuro connects to a server implementing the Neuro game API, allowing an AI backend to control Player 1. Tempest 2000 has a built-in profile; custom profiles can define other games' moves. This is opt-in and requires a separate server. Disconnects release held inputs, stopping is bounded, and hardcore achievements block AI input. See the Neuro guide for configuration and privacy details. (#1001, #1027)

Known limitations and the road to 4.0

  • Emulation threading is experimental, opt-in, and disables the Tools/debugger windows and GDB.
  • TV mode settings, overlays, achievements screens and automatic switching remain in progress.
  • Doom's attract-demo timing and the other emulation limitations documented for v3.9.1 remain.
  • Windows signing depends on the signing service's availability and approval; do not assume every Windows package is signed.

The 4.0 milestone now tracks a fully integrated app: debugging while threaded, validated 60/120 Hz display pacing, finished TV mode, and dependable installation/update flows. The hardware timing campaign and dual-Jaguar rollback remain separate future projects.

Xenowings gets its sound effects back, Doom's GPU wait loop no longer eats a RISC overclock, and the desktop app gains shaders on every package, an Interface settings tab and a new font picker.

v3.9.1 is a polish release on top of v3.9.0. For RetroArch and Provenance users it brings two DSP/GPU accuracy fixes derived from the original chip netlists, a faster GPU idle-loop fast-forward, a GDB stub that works with stock gdb, a framebuffer bounds fix, loader fixes for twelve homebrew and demo files, and working legacy MSVC Windows builds again. With default settings the cartridge corpus is byte-identical to v3.9.0 except Xenowings (sound effects now play), a frame or two of Skyhammer (a GPU divide by zero now returns the hardware's value), and the twelve files the loader now places where they were linked. No option keys were removed, no listed option values changed, and the savestate format stays v17.

Core

  • Xenowings shot and explosion sounds play again (#895, #954). A store issued right after a div normally writes the register's old value (Atari bug list item 2, modelled since v3.7.1). The jag_sim netlists show the exception: the scoreboard compares an indexed store's offset field against the divide's target as if it were a register number, and when they match the store waits for the quotient. Xenowings' sound mixer hits that case (store r7,(r14+7)), its joypad reader does not (store r8,(r14+1)), so both now behave as on hardware. Rule and citations: docs/jtrm-errata.md B25.
  • RISC divide keeps 33 bits (same PR). Divisors of $80000000 and above, 16.16 divides that overflow, and divide by zero now give the netlist's result (B26). The only corpus change is Skyhammer: frames 1488 and 2072 in a 3000-frame HLE / Fast-blitter run, audio identical.
  • GPU idle-loop fast-forward covers more loops (#957). A wait loop may now contain a long store when its address and value never change, the target is GPU local RAM, and the loop never reads what it writes; and the probe reaches the full jr range (30 bytes, was 14). Doom's wait loop is now skipped: instructions per frame on Doom EX drop from 83 M to 36 M at 1x and from 141 M to 37 M at RISC 2x, so a 2x overclock costs about the same as 1x. Video, audio and savestate hashes are identical with the change on 160 carts (six configurations including 2x), with idle skip off, and on 35 CD images in HLE and BIOS mode.
  • Framebuffer overrun fixed (#944, #946). Wild video registers (seen with a garbage custom boot ROM) could make the scanline renderer write past the end of the host framebuffer. Rows the buffer can't hold are now skipped, and a left edge past the row width is clamped; valid video states are unaffected. v3.9.0 was affected.
  • GDB remote stub works with stock gdb (#936, #948). It now serves a real 68K target description, so brew install gdb (or gdb-multiarch) connects with only set endian big. detach and kill leave the emulator running, watchpoints work (one slot), and long monitor output is no longer cut at 512 bytes; monitor trace shows the newest entries. LLDB can read memory but has no 68K target. Recipe: docs/gdb-stub-guide.md.
  • Twelve homebrew and demo files load where they were linked (#971, #972, #973, #974, #978, #979). The loader now reads plain GEMDOS/DRI 601A executables (Mandelbrot Demo) and Jaguar Server JAGR type 2 images (INTRO, INTROMOD) with their own layouts. Headerless BJL programs that used to be mapped as cartridges now load as RAM programs at $4000 (Hubble Fade, Hubble Nebula, Drumpad2), and Painter (bin) is placed at $10000. Images linked at $802000 are mapped there (Rayman Demo .jag/.rom, BadCode4 (Metal)/(Modified) (rom)). A cart whose $404 vector is erased ($FFFFFFFF) is entered at $802000 when a program starts there (Phase Zero (PD), and the Atari Jaguar Developer CD BIOS .j64, which now runs instead of showing a black screen). In a full corpus sweep 16 matrix cells improved and none regressed; no other file loads differently.
  • Legacy MSVC builds link again (#981, #982). The libretro buildbot's MSVC 2005 and 2010 Windows builds have failed since v3.9.0 on an unresolved snprintf in the debug interface. The RISC disassembler header now includes the pre-2015 shim itself. MinGW Windows builds were not affected.

The desktop app

  • Shaders everywhere. librashader is now built from source in CI, so the Intel slice of the macOS app, the AppImage and the .deb ship a working shader runtime (#955), and the Flatpak builds it as its own offline module (#953). When the runtime is unavailable, the Shader section says why and links to the docs.
  • Settings > Interface (#941). Theme, font, frame-rate display, the controls overlay, resume, library display and desktop options moved out of Video and Storage into their own tab. Config keys are unchanged.
  • Font picker (#943). Pick any font installed on the computer; favorites and recents; every name is drawn in its own typeface; and a separate monospace font for the debug windows, shown as samples. Fonts are scanned in the background the first time the list opens.
  • Smoother pacing when a game can't keep up (#956). The app no longer sleeps or waits for vsync while it is behind: Doom at RISC 300% (idle skip off) went from 45 to 52 fps on an M2, against 55 for the core alone.
  • Fixes: the BIOS selector picks the file you click when the same dump is in several folders (#940); the frame-rate label no longer draws over menus; duplicate ImGui IDs in the disc menu, option lists and cheat lists are gone.

Downloads

  • Every macOS download is signed and notarized (#989, #990): the core .dylibs, cue2cdi, the Jaguar CD tools and the app, so Gatekeeper opens them without a right-click. Until now only the app was.
  • The macOS Jaguar CD tools work on every Mac (#993, #994). The chdman in jagcd-tools-macos.zip needed Homebrew's SDL3, ran only on Apple Silicon and required macOS 26. It is now built without SDL, universal (Intel and Apple Silicon), for macOS 11 and later.
