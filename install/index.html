Install Provenance

Free iOS game emulator for iPhone, iPad, and Apple TV. Choose your install method below.

App StoreAltStoreSideStoreIPA / source Downloads & release notes

App Store

Recommended

The easiest way. Automatic updates, no computer needed. Provenance is 100% free on the App Store.

  • Works on iPhone, iPad, and Apple TV
  • Automatic updates via the App Store
  • Optional Provenance Plus for iCloud sync & priority support

AltStore

Sideload directly via AltStore. Tap "Add Source" to add the Provenance source, then install from the Browse tab.

  • Requires AltStore on your iPhone/iPad and AltServer on your Mac or PC
  • Refresh every 7 days (or use AltStore PAL on EU devices — no refresh needed)
  • Source URL: https://provenance-emu.com/apps.json

SideStore

Sideload wirelessly without a computer using SideStore. Tap "Add Source" to add Provenance.

  • Fully on-device — no Mac or PC required after initial setup
  • Refresh every 7 days using SideStore's built-in VPN trick
  • Source URL: https://provenance-emu.com/apps.json
Add to SideStore
Scan with your iPhone to add the source
Get SideStore →

IPA / Build from Source

Download the latest IPA and sideload manually, or build Provenance yourself from the open-source code.

  • Requires Xcode 16+ and an Apple Developer account (free or paid)
  • Full source available on GitHub under the Provenance License
  • See the build guide for step-by-step instructions

Which iOS IPA?

FileApp IDs usedTrade-off
Provenance-iOS-NoExtensions.ipa1No widgets, Spotlight, QuickLook, stickers, or Files.app ROM provider. Import ROMs via the built-in web server.

A free Apple ID can register only 10 App IDs per 7 days, and every embedded extension consumes one — so the full build can use up almost your entire weekly quota in a single install. The sideload feed serves the NoExtensions build for that reason; grab the full IPA above if you have a paid developer account or want the extensions.

This release is automatically updated on every successful develop push.

What’s new

What's New in 3.3.0

This is a big one. Four months of work since 3.2.1 covering iCloud sync, a completely revamped tvOS interface, video filters, and a ton of core and stability fixes.

☁️ iCloud / CloudKit Sync

  • ROMs, save states, BIOS files, and artwork now sync across devices via iCloud
  • Real-time download progress indicators when loading cloud save states
  • Auto BIOS sync on game load when available in iCloud
  • ROM metadata syncs alongside files
  • Artwork syncs after library updates
  • CloudKit records management tab in Settings
  • iCloud upsell UI for new users with empty libraries
  • Sync queue pauses during emulation and resumes after

📺 New tvOS UI (Default)

  • Completely redesigned tvOS interface now enabled by default
  • RetroWave-themed side menu with smooth animations
  • Save states browser accessible from the main UI with artwork and core name
  • "View All" saves section with per-system filtering
  • TopShelf v2: recent games and save states with artwork and timestamps
  • Cheats UI in the pause menu
  • Game "More Info" panel
  • Log viewer tab
  • Import status view in side menu
  • Search with persistent history
  • Dozens of focus, navigation, and theming fixes throughout

🎨 Video Filters & Shaders

  • Unified filter pipeline works across native and RetroArch cores
  • GB and VHS filters improved
  • Filters accessible from the pause menu
  • RetroArch GLES 3D cores now supported (Vecx/GLiden, etc.)
  • Dolphin shader/filter support
  • PPSSPP filter support

🎮 Core & Controller Fixes

  • RetroArch: Fixed player index mapping for MFi, PS4, and Xbox controllers; PS4 start/select fixed; 32x controls added; GameCube controller responder added
  • Mupen64Plus: Fixed PS4 start button; fixed tvOS scaling and placement; better save error messages
  • Dolphin: Fixed Vulkan landscape rendering
  • GenPluGX: Added CHD support; added wide-screen GameGear core
  • PicoDrive: Fixed crash on unload; fixed 32x controller mapping
  • FCEUmm: Fixed start/select button mapping
  • Mednafen: Fixed DualShock/DualSense pause/play button mapping
  • GameBatte / TGDB Dual: Fixed PSX/Xbox pause/select button mapping

🐛 Bug Fixes & Stability

  • Fixed multiple app hangs from main-thread Realm access (moved to background)
  • Fixed crash in pause menu when closing core
  • Fixed potential crash if audio ring buffer init fails
  • Fixed crash in share/import extension
  • Fixed aspect ratio issues in Stella and some other cores
  • Fixed FPS label appearing in screenshots
  • Fixed artwork not refreshing in game library after sync
  • Fixed game importer re-queuing already-imported items
  • Fixed Realm contentless core crash
  • Fixed "Continue" carousel metadata mismatch
  • Skin selector refreshes orientation previews on rotation change
  • ManicSkin/DeltaSkin files can now be opened directly from Safari
  • iPad import status modal clipped layout fixed
  • DSP audio engine fixes

⚡ Performance

  • Artwork loading significantly faster
  • Game library UI rendering optimizations (removed unnecessary Observable wrappers)
  • Async tab bar icon loading
  • CloudKit sync deduplication and repeat-lookup fixes
  • Game importer skips MD5 hashing for large non-BIOS files

What’s new

Virtual Jaguar libretro v3.9.1

Xenowings gets its sound effects back, Doom's GPU wait loop no longer eats a RISC overclock, and the desktop app gains shaders on every package, an Interface settings tab and a new font picker.

v3.9.1 is a polish release on top of v3.9.0. For RetroArch and Provenance users it brings two DSP/GPU accuracy fixes derived from the original chip netlists, a faster GPU idle-loop fast-forward, a GDB stub that works with stock gdb, a framebuffer bounds fix, loader fixes for twelve homebrew and demo files, and working legacy MSVC Windows builds again. With default settings the cartridge corpus is byte-identical to v3.9.0 except Xenowings (sound effects now play), a frame or two of Skyhammer (a GPU divide by zero now returns the hardware's value), and the twelve files the loader now places where they were linked. No option keys were removed, no listed option values changed, and the savestate format stays v17.

Core

  • Xenowings shot and explosion sounds play again (#895, #954). A store issued right after a div normally writes the register's old value (Atari bug list item 2, modelled since v3.7.1). The jag_sim netlists show the exception: the scoreboard compares an indexed store's offset field against the divide's target as if it were a register number, and when they match the store waits for the quotient. Xenowings' sound mixer hits that case (store r7,(r14+7)), its joypad reader does not (store r8,(r14+1)), so both now behave as on hardware. Rule and citations: docs/jtrm-errata.md B25.
  • RISC divide keeps 33 bits (same PR). Divisors of $80000000 and above, 16.16 divides that overflow, and divide by zero now give the netlist's result (B26). The only corpus change is Skyhammer: frames 1488 and 2072 in a 3000-frame HLE / Fast-blitter run, audio identical.
  • GPU idle-loop fast-forward covers more loops (#957). A wait loop may now contain a long store when its address and value never change, the target is GPU local RAM, and the loop never reads what it writes; and the probe reaches the full jr range (30 bytes, was 14). Doom's wait loop is now skipped: instructions per frame on Doom EX drop from 83 M to 36 M at 1x and from 141 M to 37 M at RISC 2x, so a 2x overclock costs about the same as 1x. Video, audio and savestate hashes are identical with the change on 160 carts (six configurations including 2x), with idle skip off, and on 35 CD images in HLE and BIOS mode.
  • Framebuffer overrun fixed (#944, #946). Wild video registers (seen with a garbage custom boot ROM) could make the scanline renderer write past the end of the host framebuffer. Rows the buffer can't hold are now skipped, and a left edge past the row width is clamped; valid video states are unaffected. v3.9.0 was affected.
  • GDB remote stub works with stock gdb (#936, #948). It now serves a real 68K target description, so brew install gdb (or gdb-multiarch) connects with only set endian big. detach and kill leave the emulator running, watchpoints work (one slot), and long monitor output is no longer cut at 512 bytes; monitor trace shows the newest entries. LLDB can read memory but has no 68K target. Recipe: docs/gdb-stub-guide.md.
  • Twelve homebrew and demo files load where they were linked (#971, #972, #973, #974, #978, #979). The loader now reads plain GEMDOS/DRI 601A executables (Mandelbrot Demo) and Jaguar Server JAGR type 2 images (INTRO, INTROMOD) with their own layouts. Headerless BJL programs that used to be mapped as cartridges now load as RAM programs at $4000 (Hubble Fade, Hubble Nebula, Drumpad2), and Painter (bin) is placed at $10000. Images linked at $802000 are mapped there (Rayman Demo .jag/.rom, BadCode4 (Metal)/(Modified) (rom)). A cart whose $404 vector is erased ($FFFFFFFF) is entered at $802000 when a program starts there (Phase Zero (PD), and the Atari Jaguar Developer CD BIOS .j64, which now runs instead of showing a black screen). In a full corpus sweep 16 matrix cells improved and none regressed; no other file loads differently.
  • Legacy MSVC builds link again (#981, #982). The libretro buildbot's MSVC 2005 and 2010 Windows builds have failed since v3.9.0 on an unresolved snprintf in the debug interface. The RISC disassembler header now includes the pre-2015 shim itself. MinGW Windows builds were not affected.

The desktop app

  • Shaders everywhere. librashader is now built from source in CI, so the Intel slice of the macOS app, the AppImage and the .deb ship a working shader runtime (#955), and the Flatpak builds it as its own offline module (#953). When the runtime is unavailable, the Shader section says why and links to the docs.
  • Settings > Interface (#941). Theme, font, frame-rate display, the controls overlay, resume, library display and desktop options moved out of Video and Storage into their own tab. Config keys are unchanged.
  • Font picker (#943). Pick any font installed on the computer; favorites and recents; every name is drawn in its own typeface; and a separate monospace font for the debug windows, shown as samples. Fonts are scanned in the background the first time the list opens.
  • Smoother pacing when a game can't keep up (#956). The app no longer sleeps or waits for vsync while it is behind: Doom at RISC 300% (idle skip off) went from 45 to 52 fps on an M2, against 55 for the core alone.
  • Fixes: the BIOS selector picks the file you click when the same dump is in several folders (#940); the frame-rate label no longer draws over menus; duplicate ImGui IDs in the disc menu, option lists and cheat lists are gone.

Downloads

  • Every macOS download is signed and notarized (#989, #990): the core .dylibs, cue2cdi, the Jaguar CD tools and the app, so Gatekeeper opens them without a right-click. Until now only the app was.
  • The macOS Jaguar CD tools work on every Mac (#993, #994). The chdman in jagcd-tools-macos.zip needed Homebrew's SDL3, ran only on Apple Silicon and required macOS 26. It is now built without SDL, universal (Intel and Apple Silicon), for macOS 11 and later.

Website

  • The download page is regrouped by platform and architecture, with a Nightly / Latest / Older releases picker (#958).
  • New app screenshots: achievements with real artwork, Jaguar CD, themes, debug tools, and a gdb recipe (#959).
  • The release log is generated from these notes, and the pages are current to v3.9 (#964).
  • The app page uses the same release picker as the Download page, every screenshot opens in the lightbox, and the home page has a strip of 16 game screenshots (#970).
  • Links shared on social media show a screenshot collage for the home page and a card of app screenshots for the app page, and the favicon is the app icon (#985).
  • The compatibility matrix no longer says a game runs when its 68K crashed in the first second and the screen stayed black. Those rows are now marked unverified, ? (trap_loop) (#975, #980).

Known issues

  • Doom's attract demo runs too fast at every setting; gameplay is close. The GPU finishes a frame in 1-2 fields where hardware needs 4-8 (#401). The timing options help only at RISC 1x, since an overclock speeds the GPU back up.
  • Blit Memoization, DRAM Timing and GPU/DSP Pipeline Timing switch the idle-loop fast-forward off for every game while enabled, so overclocking with them on costs the full price. Leave them off unless a title needs them.
  • Shaders are verified to load on every package, but rendering is only checked by hand on macOS (CI has no GPU).
  • Signing. Every macOS download is signed and notarized; Windows packages are not signed yet.
  • The other v3.9.0 known issues still apply (RetroAchievements for .chd/.cdi, LAN-only link play, second instance on double-click on Windows and Linux).

Upgrading

  • RetroArch / Provenance: drop-in. The core reports v3.9.1; options and savestates (v17) carry over.
  • App: install over v3.9.0. Settings carry over; the moved options appear under Settings > Interface.

What’s new

Virtual Jaguar libretro v3.9.0

RISC overclocking no longer costs more than it should, and the Virtual Jaguar desktop app ships: a standalone emulator for macOS, Windows and Linux built on the same core.

v3.9.0 brings the RISC overclock fix and new timing work to the core, and debuts the standalone desktop app (#833). For RetroArch and Provenance users the change is the overclock fix, an experimental DSP timing model behind an existing option, and measurement tooling. With default settings the core is byte-identical to v3.8.0 in the cartridge and CD boot matrices. No option keys were removed, no listed option values changed, and the savestate format stays v17.

Core

  • RISC overclock (GPU/DSP clock 0.5x, 1.5x, 2x) keeps the idle-loop fast-forward. Any non-stock RISC clock used to switch the idle-loop fast-forward off, so games that spend most of each frame in a wait loop emulated twice the cycles, all of them spinning, and a 2x overclock ran far slower than it should. The fast-forward is exact at any clock scale, so it now stays on (#891, #569, #378). Headless harness on an M4 Max, core fps at 2x:

    Title2x before2x after1x
    Doom5282135
    Alien vs Predator71204240
    Tempest 200077209225

    Video, audio and savestates are byte-identical with the fast-forward on and off at 0.5x, 1.5x and 2x on 12 titles in HLE and 7 on the real BIOS; stock 1x is unchanged. The Settings sublabel and the [perf] log line no longer name the RISC clock as a suppressor. Doom's GPU loops are still not fast-forwarded, so Doom at 2x still takes about 1.65x the time of 1x.

  • Timing work, part of the accuracy plan (#908, #408, #313). Two pieces are measurement tooling with no behaviour change: a Doom pace gate, a GPU busy-time counter and a Checkered Flag canary (S0), and a bus-traffic census with a grant-latency function (S2). The third (S1) is a DSP pipeline scoreboard plus a 16-bit external-bus timing model. It rides on the existing GPU/DSP Pipeline Timing (Experimental) option (formerly "GPU Pipeline Timing"), which stays off by default. Anyone who already had that option on now also gets the DSP model, and like the GPU model it turns the idle-loop fast-forward off. It does not improve pacing yet: with it on, Checkered Flag runs 4.9 fields per game frame against its 3.0 cap.

  • Clock scale options also accept a percentage; GDB halt timeout clamped. 175 or 175% (clamped to 25-400) is read in addition to the listed values, which map exactly as before; the GDB halt timeout is clamped to 3600 seconds (#906).

  • A private frontend channel and a debug interface that RetroArch never sees. The core can tell the desktop app about link up/down, link statistics, wire speed and crash-watchdog hits (#906, docs/app-frontend-extension.md), pick a BIOS file and boot a BIOS on its own (#910), and expose memory, registers, breakpoints and the display list to the app's debug tools (#919, docs/app-debug-tools.md). All of it is opt-in by a handshake only the app answers; under RetroArch and Provenance it is a no-op.

The desktop app

A front end of its own in app/: SDL3 for the window, audio and input, Dear ImGui for the interface, OpenGL 3.3 for presentation. It drives the core through the same retro_* API that RetroArch uses, so core options and save states behave the same. It carries the core's version number and ships with each release. It was built in #867; docs and site in #896. Screenshots: https://jaguar.provenance-emu.com/app.html

Library and artwork

  • Game library on the home screen. Your games in a grid under Cartridges, Jaguar CD and BIOS & system tabs, identified by CRC32 against the libretro database (No-Intro, Redump), with box art from libretro-thumbnails downloaded on demand and cached (#838, #881, #889). Ctrl/Cmd + scroll (or a trackpad pinch on macOS) resizes the tiles, and BIOS files anywhere under a library folder show in the BIOS tab (#899).
  • Favorites, recently played and save states. Star a game (on its tile or right-click > Add to Favorites); the games you boot are kept under Recently played. Each shows as its own tab, as a strip at the top of the Cartridges and Jaguar CD tabs, both, or not at all (Favorites & recents...). A Save states tab lists every game with states and the screenshot saved with each; click one to start the game from it. Right-click a game for Play, Load state, favorites, Show in Finder / File Explorer and Copy path (#915).
  • Covers for Jaguar CD. libretro-thumbnails has no Jaguar CD art, so discs get a readable title card, and you can set your own cover: right-click a tile > Set cover image (PNG), drop a PNG on a tile, or put <Title>.png files in the app's covers folder (#901). Until libretro-thumbnails has a Jaguar CD set, discs fall back to box art, title screens and snaps hosted on the project site (https://jaguar.provenance-emu.com/thumbnails/), asked only after libretro-thumbnails misses (#907).
  • Better disc identification. .chd discs are checksummed from their first track (like .cue), .cdi best-effort, and a disc whose checksum is not Redump's (a non-Redump bin/cue or .cdi) is matched by file or folder name when only one game fits. Hover a tile to see how it was identified (#901). CHD hashing is verified against synthetic images only; checking real Redump CHDs is still to do.

BIOS

  • BIOS choice and boot (Settings > BIOS, BIOS & system tab). Pick the exact boot ROM or CD BIOS file the core runs (any name, any folder; Auto stays the default), switch cartridges and CD games between HLE and the real BIOS without loading anything first, and Boot a BIOS on its own: the CD BIOS with no disc (its disc screen, Memory Track plugged in) or the cartridge boot ROM with an empty slot. A BIOS dropped on the window is imported, not run as a cartridge; JAGCD.BIN-style upper-case names are treated as the core's search sees them on macOS and Windows. One click copies a BIOS into the system folder under the name the core reads (#910, #899, #838).

What’s new

Virtual Jaguar libretro v3.8.0

Correct by default. Flip Out runs, Fight For Your Life boots on the real BIOS, Club Drive has sound under HLE, White Men Can't Jump stops tearing, and Doom netplay holds 60 fps.

v3.8.0 is the "Correct by default" release (milestone "v3.8.0 — Correct by default", epic #746). It fixes titles that needed a non-default setting or misbehaved in one boot mode, makes the per-title database explain itself in the frontend, and adds a release gate that blocks a tag when any corpus row moves backward. There is one new core option (the GameDrive SD card) and one new value for an existing option. The savestate format moves from v16 to v17; v3.7.1 and older states still load (see Savestates).

Several fixes here are verified headlessly only, not yet in RetroArch. Each one says so below, and they are collected under Known issues.

Highlights

  • Flip Out runs in both boot modes. 1, 2 and 4 MB cartridge images now repeat across the cartridge window as on hardware (#855, #851).
  • Fight For Your Life (1996) boots on the real BIOS. Power-on RAM is now zero-filled in BIOS mode, as it already was in HLE (#868, #856).
  • Club Drive has audio under the default HLE boot. DSP interrupts are taken at the DSP's next instruction instead of inside an event callback (#849, #744).
  • White Men Can't Jump gameplay stops tearing at default settings, through a new "68000 only" value for Blitter Bus Timing (#870, #736).
  • Music Demo, Ruiner Pinball and Native Demo (bin) no longer run their DSP or GPU into garbage (#862, #869, #872, #873).
  • Doom 2-player netplay holds 60 fps instead of dropping to 30 Hz. Play over Wi-Fi is still slower than single player (#861, #871, #860).
  • The GameDrive SD card works, backed by a folder on your device (#844, #783).
  • The frontend explains per-title presets, and options that apply only at load say so (#847, #859, #863).

Game fixes

Cartridge titles

  • Flip Out (#851, #855). The game checks the long at $A02000 and executes ILLEGAL if it does not match. A 2 MB cartridge drives only the address lines it has, so on hardware its image repeats at $A00000; the core returned 0 there. HLE looped ILLEGAL/RTE from about frame 320 and BIOS trapped into the boot ROM at about frame 810. Images of exactly 1, 2 or 4 MiB are now mirrored (1 MB every MB, 2 MB at $A00000 and $C00000, 4 MB once at $C00000), matching the MiSTer core's cart_mask; the JTRM is silent on this. In a headless run HLE reaches the high-score screen by frame 1000 and BIOS the title screen by frame 1200. A 160-cart A/B changed only Flip Out, plus one pixel in Fight For Your Life, where a blit reads past the end of the 4 MB image. The cart window past an image is also cleared on load, so a previous title's bytes no longer survive a reload in the same session. Headless-verified only.
  • Fight For Your Life (1996), real BIOS (#856, #868). The game sizes a fill from a RAM word nothing ever writes. BIOS mode filled power-on RAM with a per-word random pattern, so the fill overran into the GPU's parameter block, the GPU wrote a bad pointer, and the 68K took an address error into the boot ROM at frame 1032. HLE zero-fills and never hit it. BIOS mode now zero-fills too. Power-on DRAM contents are undefined on hardware, but real parts come up in near-uniform runs, not independent random words. RAM-loaded images and the first 8 bytes are still preserved. One known cost: the JaGol intro seeds its Game of Life from power-on RAM and now shows an almost empty field (see Known issues). test_ffyl_856 now runs 1400 frames to game code. The good dump is CRC B14C4753; the [a1] dump is an authentic BIOS reject. Headless-verified only.
  • Club Drive audio under HLE (#744, #849). Club Drive was silent under the default HLE boot (in a sweep of 97 start-up I2S phases, 5 were silent on develop and 0 with the fix). The core vectored the DSP inside the I2S event callback; the 68K then rewrote D_PC while the DSP was running (JTRM v8 p.110 allows that only while it is idle), so the interrupt service routine never ran and the game never re-armed it. The interrupt is now latched and taken at the DSP's next instruction. Club Drive HLE went from RMS 0.0 to 2948.6. A 160-cart A/B was framebuffer-identical in both modes, and the audio pair is unchanged on Wolfenstein 3D, Doom, White Men Can't Jump, Iron Soldier 1 and 2, Skyhammer, Atari Karts, Raiden, Tempest 2000 and Zoop. Confirmed by ear in RetroArch on iOS (Doom, Wolfenstein 3D, Club Drive, Music Demo).
  • White Men Can't Jump gameplay tearing (#736, #870). v3.7.1 turned Blitter Bus Timing on for this title to fix its intro logo. That also made the GPU wait out each of its own blits at worst-case cost, so the GPU's draw started late and in 86 of 125 fields was still running when the 68000 swapped buffers: horizontal tears and sprites missing for a field. Blitter Bus Timing gains a "68000 only" value that stalls just the 68000, and the title's preset now uses it. The intro logo fix still holds (boot frames 0-300 hash identically; the logo is 43.8% lit). Over two 600-frame stretches of the attract match, reverted frames / spliced frames went from 68/12 and 95/15 to 21/2 and 23/4. Some flicker remains. Headless-verified only (fb_flicker_probe).
  • Music Demo DSP runaway (#853, #862). The DSP code stores D_FLAGS to change register bank and then sets r31 in the next instruction. On hardware that instruction still sees the old bank (JTRM v8 p.109); the core switched immediately, so the stack pointer landed in the wrong bank and the first interrupt returned into garbage. The bank switch now waits out the two-instruction retire window, and jump/jr commit it before their delay slot so the Doom and Wolfenstein 3D epilogues behave as before. A 160-cart A/B (HLE and BIOS, 1200 frames, framebuffer and audio) was byte-identical except Music Demo. The crash watchdog now also sees DSP runaways in HLE. Confirmed in RetroArch on iOS: Music Demo runs in both modes with no watchdog lines.
  • GPU G_FLAGS retire window (#865, #869). The GPU gets the same two-instruction window as the DSP. No title is known to change. Unit-tested (test_gpu_ops 66/66). A partial corpus A/B (98 carts, 1200 frames) was 98/98 identical in HLE and 96/98 in BIOS, the two differences being harness artifacts, and the release cart matrix (which includes this change) has no backward row. A per-frame A/B of the whole corpus and a visual check are still owed.
  • Ruiner Pinball GPU escape (#866, #873). store Rn,(r15+Rm) was the one GPU long-store form that did not drop the low address bits, so a word-aligned store split across two longs, a jump table went wrong and the GPU ran off into DSP RAM at frame 56. Every form now aligns, as the MiSTer RTL addresses GPU local RAM by bits 11:2 only. Ruiner Pinball loses its gpu_pc_escape and video_stall in both modes. The core does not yet claim the game is playable. Headless-verified only.
  • Native Demo (bin) boots (#866, #872). This headerless binary is linked at $5000, but every address it uses also fits $4000, so the loader picked $4000 and the GPU ran away at frame 1. On a tie the loader now prefers the base under which LEA targets point at Jaguar I/O descriptor tables. Across 141 resolvable carts only this title changes base. It now reaches game code with video in both modes, like the .jag version. Headless-verified only.
